## 3. 방식 후보 비교
정확도·속도 수치는 이 문서에서 **측정하지 않았다**. 모든 칸은 일반 특성이고, 수치는 `미확인`(한국어 샘플 5~10개로 벤치마크 필요).

| 항목 | A. 로컬 오픈소스(whisper.cpp 등) | B. 외부 API 선택형(예: OpenAI 전사) | C. 둘 다(기본 로컬, 외부는 켜면 사용) |
|---|---|---|---|
| 한국어 정확도 | 모델 크기에 비례. 작은 모델은 한국어 오인식 가능성 높음. `미확인` | 대체로 높은 품질 기대. 모델·정확도 `미확인` | 사용자가 품질/개인정보로 선택 |
| 비용 | 라이선스·호출비 0, 서버 CPU 사용 | 분당 과금(요금 `확인 필요`, 현재 가격표 조회 전) | 외부 쪽만 과금 |
| 속도 | CPU만 쓰면 모델에 따라 실시간보다 느릴 수 있음. `미확인` | 네트워크+서버 처리, 일반적으로 빠름. 파일 크기 상한 `확인 필요` | 위와 동일 |
| 개인정보 | 음성이 서버 밖으로 나가지 않음 | 음성이 외부 사업자로 전송됨 → 동의·고지 필요(5장) | 외부는 동의 후에만 |
| 배포 | 모델 파일(수십 MB~수 GB, 크기별 상이 `확인 필요`)·바이너리 필요. 이미지에 넣으면 커지므로 볼륨 다운로드 권장. CPU/RAM 요구 `미확인` | 이미지 변화 없음(ffmpeg는 이미 있음). env 키만 | 로컬 쪽 부담을 그대로 가짐 |
| 라이선스 | whisper.cpp·Whisper 모델 가중치 모두 MIT로 알려졌으나 **버전별 `확인 필요`** | 약관·데이터 보존 정책 `확인 필요`(`store:false`류 옵션 존재 여부) | 둘 다 확인 |
| 최신 stable | whisper.cpp 버전 `확인 필요`(작업 시점 릴리스 페이지에서 확정) | API 모델명 `확인 필요`(env로 주입, 코드에 고정 금지) | — |
| 구현 난이도 | 바이너리 호출·모델 관리·타임아웃 | HTTP 1개, 파일 업로드 | 어댑터 인터페이스 1개로 둘 다 |

- 다른 로컬 후보(faster-whisper 등 Python 계열): Node 이미지에 Python 의존성이 늘어 배포 복잡 → 1차 비교 대상에서는 제외, 필요하면 후속(`확인 필요`).

## 4. 데이터 흐름·비동기 작업
1. 업로드: 기존 `POST /api/media`로 영상 저장(소유자 = 세션, task-008 후).
2. 전사 요청: `POST /api/transcripts {mediaId, engine, language}` → 작업 기록 생성(`queued`), 작업 ID 반환.
3. 추출: ffmpeg로 모노 16kHz WAV 추출(임시 파일, 작업 종료 시 삭제). 영상 길이 상한 초과 시 거부(상한 `미정`, Q4).
4. 전사: 어댑터(`local`/`remote`)가 구간 `{start,end,text}[]` 반환. 로컬은 자식 프로세스+타임아웃, 외부는 파일 크기 상한 내 분할 전송.
5. 저장: 작업 JSON(`transcripts/<id>.json`: `ownerId`·`mediaId`·`status`·`progress`·`segments`·`engine`·`error`). 상태 `queued → extracting → transcribing → done | failed | canceled`.
6. 진행률: 화면이 `GET /api/transcripts/:id`를 폴링(2~3초). 추출은 ffmpeg 시간 기준 %, 전사는 구간 개수 또는 처리 시간 기준(세부는 구현 때 결정).
7. 자막 편집: 구간 목록을 편집(문장 수정·병합·분할·시간 조정) → 자막 템플릿 문장·시간으로 채움 → 기존 렌더 파이프라인으로 MP4.
8. 실행 제어: 렌더와 같은 전역 직렬 큐 vs 별도 큐 `미결`(Q5). 서버 재시작 시 `queued/running` 작업은 `failed(interrupted)`로 정리.
- 자막 템플릿에 구간 시간 필드가 아직 없음 → `lib/content-templates.ts` 데이터 모델 확장 필요(기존 입력 문장 방식과 호환 유지, 기본값 유지).
- 다이어그램 요청: 시퀀스 — 사용자·UI·API·큐/작업 저장·ffmpeg·전사 어댑터(local/remote)·렌더(요청→폴링→완료).

## 6. 위험·열린 결정
- 위험: 한국어 정확도 미달로 기능 체감 실패 / CPU 전용 서버에서 로컬 전사가 너무 느림 / 모델 파일로 이미지·볼륨 용량 증가 / 외부 전송 동의 누락 / 작업 중 서버 재시작 / 렌더 큐와 CPU 경합.
- 사용자에게 물을 것(팀장 결정 필요):
  1. 방식: A(로컬만) / B(외부만) / C(둘 다). 외부는 어느 사업자(OpenAI 외)까지 허용?
  2. 처리 서버: 현재 호스트의 CPU·RAM·GPU 사양과 동시 사용자 수(`미확인`, 측정 필요).
  3. 외부 전송 허용 대상: 운영자만 / 모든 로그인 계정. 고객 음성 전송에 대한 고지 문서 변경 여부.
  4. 영상 길이·파일 크기 상한(예: 몇 분)과 목표 처리 시간.
  5. 전사 작업을 렌더와 같은 직렬 큐에 둘지, 별도 1건 큐로 둘지.
  6. 필요한 결과 형태: 자막 템플릿 채우기만 / SRT·VTT 내보내기 포함 / 단어 단위 시간.
  7. 지원 언어: 한국어만 / 영어 혼용 / 자동 감지.
  8. 비용 상한: 외부 API 월 예산, 계정별 한도 필요 여부.
  9. task-008(다계정)을 먼저 끝내고 시작할지(권장), 병행할지.
- 수익·사업 관점: 수익 모델·검증 방법·정부지원 연결은 `미확인`(근거 필요). 자막 자동화는 숏폼 제작 대행 효율과 연결되나 수치 근거 없음.

## 7. 권장안·완료 조건 초안
- 권장안(미확정): **C. 어댑터 구조로 로컬 + 외부 선택형**. 1차 구현은 로컬 whisper.cpp(소형 모델)로 한국어 샘플 벤치마크 후 합격 시 로컬 기본, 불합격이면 외부(운영자만) 우선. 앞서 Q2·Q4 답이 필수. task-008 완료 후 착수.
- 분해 후보(작업당 한 세션): ① 벤치마크(샘플 5~10개, 정확도·시간 측정, 버전 확정) ② 어댑터·작업 저장·API ③ 자막 편집 UI·템플릿 시간 필드 ④ 동의 UI·보안 테스트.
- 완료 조건 초안:
  - `npm run typecheck`, `npm test`, `npm run build` 통과.
  - 한국어 샘플에서 목표 정확도 기준 충족(기준 수치는 벤치마크 후 확정, `미확인`).
  - 계정 A·B 세션 테스트: 남의 전사 작업·미디어 접근 404, `ownerId` 입력 무시.
  - 외부 방식: 동의 없이는 호출 0건(모킹 검증), 키 없으면 비활성, 로그에 텍스트·키 없음.
  - 상한 초과·취소·서버 재시작 시 작업 상태·임시 파일 정리.
  - 기존 입력 문장 방식 자막 템플릿 회귀 없음.
- 수동(팀장): Docker에서 실제 영상 전사 → 자막 편집 → MP4 렌더 1회.

## 8. 사용자 결정 (2026-11-02, 이 장이 1~7장보다 우선)
- 방식: **로컬 우선 + 외부 선택(C안)**. 먼저 로컬 엔진의 한국어 품질·속도를 측정하고, 외부 API는 운영자만 켤 수 있는 선택 기능으로 둔다(키는 서버 환경 변수, 음성 외부 전송은 켤 때 고지).
- 결과: **자막 템플릿 채우기 + SRT 내보내기**(단어 단위 시간은 범위 밖).
- 위험 높음(새 의존성·외부 전송·장시간 작업) → 착수 전 challenger, 새 의존성은 security-baseline(라이선스·SBOM).

## 9. challenger REVISE 반영 (2026-11-02, 팀장 기본값 — ❓는 사용자 확인 필요. 이 장이 1~8장보다 우선)
1. 로컬 엔진: whisper.cpp를 Docker 멀티스테이지에서 **소스로 빌드**한다(태그·커밋 고정, 실행 파일만 복사). npm 래퍼처럼 postinstall이나 런타임에 내려받는 방식은 금지한다. 모델은 출처 저장소·리비전·SHA256을 고정하고, 운영자 CLI `npm run stt:model`로 서버를 정지한 상태에서 받는다. 검증에 실패하면 로컬 엔진을 끈다. SBOM·라이선스(코드와 가중치 각각)는 수동 항목으로 둔다.
2. 모델 위치: 백업 대상이 아닌 별도 읽기 전용 볼륨 `/app/models-stt`(로컬은 `.stt-models/`, .gitignore에 추가).
3. 길이 상한: 오디오·영상 공통으로 `durationSeconds` 300초(기존 영상 상한과 같음) ❓. 16kHz 모노 WAV 한 파일로 처리하고 분할 전송은 MVP에서 뺀다.
4. 실행: 렌더와 같은 worker 패턴(pid 생존 확인, 지연 판정, cancel 파일)을 쓰고 **같은 `render.lock`을 공유해 직렬로 처리**한다 ❓. 취소·타임아웃(기본 10분) 때는 프로세스 트리 전체를 끝낸다(Linux는 프로세스 그룹, Windows는 taskkill /T). 스레드 수는 env로 정한다.
5. ffmpeg: 저장된 mimeType에 맞춰 `-f`를 강제하고 `-protocol_whitelist file -nostdin -map 0:a:0 -t 300`을 쓴다. 오디오가 없으면 failed로 끝낸다.
6. 외부 전사: 운영자만 쓸 수 있고 **운영자 본인 소유 미디어만** 보낼 수 있다. 요청할 때마다 동의 플래그를 서버가 확인하고(없으면 외부 호출 0건), AbortSignal 타임아웃을 건다. 키·모델 env는 `websiteAiConfigured`와 분리한다. 매번 동의할지 켤 때 한 번만 동의할지 ❓, 국외 이전 고지 문서를 바꿀지 ❓.
7. SRT: `HH:MM:SS,mmm`, CRLF, UTF-8(BOM 없음). 빈 줄·`-->`·CR은 정규화하고 `<…>`·`{…}` 태그를 제거하며 한 구간은 최대 2줄. 내용은 편집본 기준이다. 파일 이름은 ASCII 대체 이름과 `filename*`로 넣는다. 내보내기 라우트도 고정 404 소유 검사를 한다.
8. 계정 분리: `scripts/owner-data.cjs` OWNER_DIRS에 `transcripts`를 추가하고, test-ownership 라우트 표에 새 라우트를 넣는다. 미디어를 삭제하면 그 미디어를 참조하는 전사도 삭제한다.
9. 출력 상한: 구간 500개, 구간당 200자. start<end이고 단조 증가하며 길이 이내여야 한다. 이 검사는 `validateProject`에 넣는다.
