# Motion Studio — 제품 기획 v0.2

> 2026-10-30 범위 변경: 도면 생성·법규 판정·새 CAD 모델링은 현재 개발에서 제외합니다. Arch-Studio와 겹치는 부분은 참고하고 가져온 파일의 검증·미리보기·웹/3D/영상 제작을 진행합니다. 아래 기존 CAD 생성안보다 [파일 기반 제작 기준](../architecture/IMPORT_WORKFLOW.md)이 우선합니다.

작성일: 2026-10-29. 기준: 기존 Photo Wall PRD와 사용자의 통합 Motion Studio·15초 자동 인트로 요청.

## 제품 정의

2026-10-30 구현 확장: 모션 프리셋 13종·720p/1080p/1440p/4K 출력, 전역 좌측 GNB·우측 콘텐츠, [공통 레퍼런스 워크플로](../references/REFERENCE_WORKFLOW.md), 메타데이터 기반 웹 초안·Awwwards/Dribbble 탐색과 자체 디자인 매핑, [CapCut 미디어 전달](../features/video/CAPCUT_EXPORT.md), [네이버 홈페이지형 블로그 제작기](../features/blog/NAVER_BLOG_STUDIO.md)를 추가한다. 블로그는 수동 적용용 이미지·위젯 패키지이며 계정 자동 설치가 아니다.

Motion Studio는 사용자가 제공한 벤치마크 사이트, 이미지, 로고와 사업 정보를 바탕으로 프리미엄 동적 웹페이지를 제작하고, 같은 브랜드 자산으로 3D 갤러리·모델 뷰어와 영상을 만드는 제작 플랫폼이다. 웹사이트 생성기는 핵심 제품 트랙이다. 벤치마크의 구조와 모션 특징을 분석해 사용자의 브랜드에 맞는 새 페이지를 만들고 미리보기·수정·배포/내보내기까지 잇는 것이 목표다. 사진 6~36장 + 로고 → 15초 유튜브 인트로는 현재 가장 앞서 있는 별도 제작 흐름이다. 현재 실행 형태는 로컬 단일 사용자이며, 인터넷에 배포된 다중 사용자 SaaS를 의미하지 않는다.

## 세 작업 공간

| 작업 공간 | 지금 제공하는 범위 | 후속 상품화 범위 |
| --- | --- | --- |
| 웹사이트 제작 | `/websites` 브랜드 입력·저장·재열기·섹션 편집·단일 HTML 출력, `/showcase` 모션 데모 | 벤치마크 URL/이미지 + 브랜드·페이지 정보 입력 → 섹션·디자인 분석 → 반응형 동적 페이지 생성 → 시각 편집·미리보기 → 배포/내보내기 |
| 3D 갤러리·뷰어 | R3F 사진월 및 GLB 뷰어 시제품 `/gallery`, `/architecture/viewer` | 에셋 등록·공간 구성·객체 정보·카메라/인터랙션 편집을 지원하는 제작 흐름 |
| 영상 자동화 | 사진·로고 기반 15초 템플릿, 세부 편집기, 서버 렌더 | 랭킹 쇼츠, 자동 자막, 제품 비교, 반복 작업 |

현재 웹 제작기는 브랜드 랜딩 템플릿의 섹션 편집·저장·HTML 출력을 제공한다. 벤치마크 자동 분석과 자유 배치 편집은 미구현이며 3D 공간 제작 편집기는 후속 단계다. 벤치마크를 그대로 복제하는 도구가 아니라 페이지 구조·시각 언어를 참고해 새 브랜드 결과물을 만드는 방향으로 설계한다.

## 첫 고객 경험

1. 대시보드의 `15초 영상 만들기` 선택.
2. 기존 라이브러리의 사진을 선택하거나 새 사진 등록.
3. 로고 이미지를 등록·선택. 브랜드명은 선택 사항.
4. `15초 인트로 자동 생성` → 프로젝트 저장 → 불변 스냅샷 → 렌더 작업 시작.
5. 렌더 작업에서 진행률 확인 → MP4 재생·다운로드.
6. 필요할 때만 편집기로 이동하여 배경·타일·브랜드·음악·길이 조정.

로고와 사진은 다른 에셋이다. 로고를 사진월에 중복 사용하지 않는다. 업로드된 원본과 프로젝트 참조, 렌더 시점 파일 사본을 구분한다. 생성 실패 시 저장된 프로젝트에서 다시 시도할 수 있어야 한다.

## 15초 템플릿 계약

- ID: `photo-wall-intro-v1`, templateVersion: 1, contentType: intro.
- 필수: 서로 다른 사진 6~36장, 로고 이미지 1개.
- 선택: 브랜드명 80자 이하. 빈 문자열이면 로고만 엔딩에 표시.
- 출력: 1920×1080, 30fps, 15초, 450프레임, H.264 MP4.
- 연출: 클로즈업·줌아웃 → 사진월 이동 → 11.8~15초 로고·브랜드 엔딩.
- 사진·로고를 바꿔도 시간축·카메라·파일 규격은 템플릿에서 고정한다.
- 세부 편집기는 기존 10초 프로젝트도 그대로 열 수 있다. 스키마 버전 1과 기존 프로젝트를 보존한다.

## 설계 경계

- SVG 래스터화 표준: 웹 앱과 향후 데스크톱 앱에서 비트맵이 필요할 때 Rust **resvg**를 사용한다. SVG 원본을 유지하고 PNG 다운로드·썸네일·텍스처·정적 영상 합성용 파생물을 생성한다. 공통 계약과 런타임별 어댑터는 구현 예정이며 상세는 [SVG 래스터화 기획](../architecture/RASTERIZATION_SPEC.md)을 따른다.

- 프런트엔드: Next.js·TypeScript, 대시보드와 모듈별 화면.
- 에셋·프로젝트: 파일 ID, 원본·파생 관계, JSON 저장·검증.
- 모션: `sceneState(t)`와 카메라·배치 계산. Date.now·Math.random·실시간 누산을 영상 씬에 사용하지 않는다.
- 웹 시계: GSAP. 웹 스크롤: ScrollTrigger. 3D 상호작용: R3F·OrbitControls.
- 영상 시계: Remotion frame/fps. 자산 준비를 기다린 뒤 명시적으로 프레임을 그린다.
- 렌더: Node 워커, 설정+에셋 사본, FFmpeg 인코딩, 실제 프레임 검수.
- 플랫폼 입력: `lib/template-catalog.ts`. 준비된 compositionId를 가진 템플릿만 실행한다.

## 대시보드 디자인

- 이름: Motion Studio. 다크 네이비 바탕과 보라색 강조, 사진 중심 화면.
- 첫 화면: 제작 CTA → 웹·3D·영상 3개 작업 공간 → 실제 작업 수 → 프로젝트 → 공통 미디어 → 콘텐츠 카탈로그.

- 구조도: `/architecture`, 원본 `public/architecture.svg`. 변경 가능한 텍스트 구조는 ARCHITECTURE.md.

현재 개발 범위는 통합 대시보드, 세 작업 공간의 기반·프리뷰, 15초 자동 인트로다. 랭킹·자막·비교는 이 기획에 따라 다음 반복에서 구현하며 현재 동작한다고 선언하지 않는다. 상업 출시 전에는 실제 브랜드 자산, 원본 화질, 렌더 비용·실패율, 사용자 시각 검수를 확인한다. 기간과 매출은 실측 없이 약속하지 않는다.

## AI 건축 제작 확장 — v0.3 기획 추가

기존 3D 공간 모듈에 **AI Architectural Studio** 트랙을 추가한다. 상세 계획은 [ARCHITECTURAL_STUDIO_PLAN.md](../architecture/3d/ARCHITECTURAL_STUDIO_PLAN.md)다.

- 제작: Rhino·Grasshopper 건축 모델, Fusion 정밀 부품, 필요 시 Blender 최적화.
- 연결: MCP/CLI 어댑터의 기능 탐색·테스트·단일 작성자·변경 전후 검증.
- 자산: CAD 원본 → 검증된 엔진별 파생 모델 → 층·객체·재질 ID 메타데이터.
- 출력: B1 R3F 건축 웹 뷰어 우선 → B2 Unity Web 체험 → B3 Unreal GPU·Pixel Streaming.
- 상품: 건축 뷰어·가상 전시관·모델하우스·건축 영상, 이후 반복 제작·SaaS 검토.

이는 기존 웹·영상·콘텐츠 확장을 대체하지 않는 공간 모듈의 확장 계획이다. 현재 연결된 CAD·엔진이나 완성된 건축 뷰어로 표시하지 않는다. 도구 설치·연결·모델링·클라우드 배포는 후속 작업이며 이번 요청에서는 기획과 다이어그램을 갱신한다.


### 디자인 모듈 참고 적용

nomad-design-modules의 가이드를 참고해 웹사이트 제작기에 미니멀·퍼블리케이션·포트폴리오 디자인 키트를 추가했습니다. 서체·여백·모서리·첫 화면 모션이 미리보기와 HTML에 함께 적용됩니다. 기존 프로젝트는 이전 디자인을 유지합니다. 출처와 제작기별 적용 범위는 [디자인 모듈 적용 계획](../design/DESIGN_MODULE_INTEGRATION.md)에 정리했습니다.


### 탐색·계정·웹사이트 시작 화면

랜딩(`/`), 대시보드(`/studio?view=dashboard`), 로그인(`/login`)의 진입 목적을 구분했습니다. 로그인 성공과 이미 로그인한 사용자의 로그인 페이지 방문은 대시보드 첫 화면으로 연결합니다. 전역 상단바에서 로그인 계정을 확인하고 로그아웃할 수 있습니다. 로컬 계정과 7일 세션을 제공하며 외부 OAuth, 메일 인증·비밀번호 재설정, 계정별 프로젝트 권한은 별도 확장입니다. 웹사이트 제작기는 유형 선택 카드에서 기본형(스튜디오/미니멀/서비스·문의), 중급형(에디토리얼/퍼블리케이션/소개 포함), 고급형(갤러리/포트폴리오/소개 포함)을 선택해 편집을 시작합니다.


### BASIC · BUSINESS · PREMIUM 상품화

웹사이트 제작기를 고객 과제에 따른 세 상품으로 개편했습니다. 선택 이유·제안 가격·추가 구축 범위를 비교하고, 등급별 제작 브리프를 입력·저장·JSON으로 출력합니다. 세부 전략과 구현 범위는 [홈페이지 상품 전략](../features/websites/WEBSITE_SERVICE_PRODUCTS.md)을 참고하세요. 이전 기본형·중급형·고급형 표기는 새 상품명으로 대체합니다.


### 고객 개발요구사항 진단·접수

홈페이지 제작기 상단 카드에서 고객 진단 페이지를 열고, 체크한 기능과 목적을 바탕으로 홈페이지 상품·홈페이지형 블로그를 추천합니다. 담당자·회사·전화·이메일과 동의 후 보내면 SQLite DB에 저장됩니다. 로그인한 운영자는 `/requirements-inbox`에서 조회하고 구글시트용 CSV를 받을 수 있습니다. 공개 배포·관리자 설정과 오프라인 파일의 구분은 [접수 운영 안내](../features/websites/WEBSITE_REQUIREMENTS.md)를 참고하세요.


### 제작 기본 설정

GNB 하단 설정(`/settings`)에서 영상 기본 해상도·모션 프리셋, 홈페이지 기본 테마·강조색, 네이버 블로그 기본 스타일·강조색을 저장합니다. 설정은 현재 브라우저의 로컬 저장소에 보관되고 새 제작의 시작값으로 적용됩니다. 기존 프로젝트를 열 때는 저장된 프로젝트 설정을 우선합니다. 설정 저장 실패는 화면에 표시하며 기본값 복원을 지원합니다.


### 상품 체계·앱 테마·콘텐츠 템플릿 확장
