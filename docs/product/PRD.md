## 0. 문서의 목적과 용어

본 문서는 기존 프로젝트를 폐기하지 않고 개선·확장하기 위한 단일 제품 요구사항 문서다. 개발 에이전트는 `PRD.md`를 요구사항의 기준으로 삼되 현재 소스·의존성·실행 상태를 먼저 점검하고, 확인되지 않은 구현 완료를 선언하지 않는다.

- **MVP**: 본인 사용을 위한 로컬/단일 관리자 버전. 팀·고객·결제 기능은 제외.
- **3D Photo Wall**: 여러 이미지 타일을 배치한 3차원 장면과 카메라 움직임.
- **웹사이트 생성기**: 벤치마크 URL/캡처와 브랜드 이미지·정보를 입력받아 분석·구성한 뒤, 편집 가능한 반응형 동적 페이지를 생성하는 핵심 제품.
- **3D 제작 모듈**: 동일한 브랜드 프로젝트의 이미지 갤러리 또는 3D 모델을 웹에서 구성·탐색하게 하는 제작 도구.
- **프로젝트**: 사진, 배열, 타임라인, 브랜딩, 렌더 설정을 묶은 저장 단위.
- **템플릿**: 편집 가능한 기본 레이아웃 및 카메라 경로 프리셋.
- **영상 출력**: 1920×1080 MP4(H.264) 파일 생성. 4K는 후순위.
- **원본 재현**: 디자인과 움직임의 구조를 벤치마킹하되 타인의 이미지, 로고, 음악은 무단 재사용하지 않음.

### 0.1 이번 5단계의 고정 우선순위

| 단계 | 사용자 지정 작업 | 개발 결과 | 단계 게이트 |
| --- | --- | --- | --- |
| 1차 | 기본 3D 모자이크 및 카메라 | 기존 소스의 실행 안정화·기준점 확정 | 웹/Studio 실행 및 기본 3D 장면 정상 표시 |
| 2차 | 원본 영상과 모션 정밀 비교 | 타일 간격·각도·속도·카메라 궤적 보정 | 기준 프레임 비교 승인 |
| 3차 | 로고·브랜드·음악·타이틀 편집 | 완성형 인트로 | 10초 타임라인/오디오 동기화 승인 |
| 4차 | 이미지 업로드·템플릿 관리자 | 반복 제작 자동화 | 프로젝트 저장→다시 열기→수정 성공 |
| 5차 | MP4 렌더링 및 다운로드 UI | 영상 제작 서비스 MVP | 실제 MP4 출력/다운로드 및 재생 검증 |

> **현황 판단**: 1차 소스는 제작되었다는 이전 상태를 참조하되, 사용자 환경에서 포트 접근 제한과 Remotion 정적 자산 경로 오류가 관측되었으므로 **1차 완료를 최종 승인하지 않는다**. 우선 안정화 검증부터 시작한다.

## 1. 문제 정의

### 1.1 해결할 문제

- 하나의 인트로 모션을 웹과 영상용으로 따로 제작하면 디자인/시간축이 어긋나고 수정 비용이 중복된다.
- 영상마다 사진·브랜드·타이틀을 반복 수작업으로 수정해야 한다.
- 웹 브라우저의 실시간 렌더와 Remotion의 프레임 기반 렌더는 생명주기와 에셋 경로가 달라 오류가 발생하기 쉽다.
- 수많은 이미지가 있는 3D 씬은 성능, 이미지 로딩, 모바일 대응을 체계적으로 관리해야 한다.

### 1.2 제품 목표

1. 벤치마크 사이트와 사용자가 제공한 이미지·로고·브랜드/페이지 정보를 입력해 프리미엄 반응형 웹페이지를 생성한다.
2. 생성 결과를 동적 모션 프리뷰에서 확인하고 내용을 수정·재생성하며 배포 또는 내보낼 수 있게 한다.
3. 같은 프로젝트 자산으로 3D 갤러리와 3D 모델 뷰어를 구성·제작한다.
4. 사진 6~36장과 로고로 유튜브용 15초 MP4를 반복 생성한다.
5. 공통 에셋·브랜드·프로젝트 명세를 사용해 웹·3D·영상 결과 간 일관성을 높인다.

### 1.3 비목표(이번 MVP에서 제외)

초기 MVP에서는 회원가입/구독결제, 다중 조직, 클라우드 렌더 팜, 완성형 NLE, 공동 실시간 편집, SNS 자동 업로드를 제외한다. 웹 생성의 벤치마크 입력·분석·페이지 생성·수정·내보내기는 핵심 범위다. 3D 모델 업로드·갤러리 구성을 3D 모듈 범위로 정의한다.

## 2. 타깃 사용자 및 사용 시나리오

- **우선 사용자**: 자체 유튜브 채널과 브랜드 웹사이트를 운영하는 1인 제작자.
- **향후 사용자**: 소형 영상 제작 대행사, 온라인 판매자, 크리에이터.

**주요 유저 스토리**

- US-01: 사진 36장을 업로드한 뒤 3D 사진 월을 미리 보고 싶다.
- US-02: 원본과 비슷하게 카메라가 확대·축소·이동하도록 타임라인을 조절하고 싶다.
- US-03: 로고·타이틀·배경·음악을 바꾸고 10초 인트로를 완성하고 싶다.
- US-04: 저장한 프로젝트를 다시 열어 수정하고 싶다.
- US-05: 영상 결과를 MP4로 다운로드하고 웹 히어로에도 적용하고 싶다.

## 3. 제품 범위 및 성공 지표

### 3.1 MVP 완료의 정의

- 크롬 계열 데스크톱 브라우저에서 포토월이 정상 렌더링된다.
- 사진 36장 로딩 중 실패 항목을 UI에서 식별할 수 있다.
- 10초 타임라인을 재생·정지·스크럽·반복 가능하다.
- 로고·제목·음악의 적용 시작/종료 구간을 지정할 수 있다.
- 이미지 업로드와 순서 변경, 템플릿 선택이 된다.
- 프로젝트 저장/불러오기 후 설정이 일관되게 재현된다.
- 동일 프로젝트로 웹 미리보기와 MP4를 생성한다.
- 1080p/30fps/10초 MP4가 출력되며 외부 플레이어에서 영상·오디오 확인이 가능하다.

### 3.2 비기능 지표(초기 목표, 검증 후 확정)

| 항목 | 목표 | 검증 방법 |
| --- | --- | --- |
| 길이 | 기본 10초, 사용자 설정 5~30초 | 타임라인과 출력 메타데이터 비교 |
| 해상도 | 1920×1080 기본 | ffprobe 또는 파일 속성 확인 |
| 프레임 레이트 | 30fps 기본, 60fps 실험 옵션 | 파일 메타데이터 확인 |
| 에셋 | MVP 권장 36장, 최대 60장 시험 | 유효성/메모리 테스트 |
| 안정성 | 동일 입력에서 프레임 결과 결정적 | 동일 프레임 반복 렌더 픽셀 비교 |
| 사용자 경험 | 이미지 누락 시 흰 화면 대신 대체 표시 및 오류 메시지 | 파일 누락 시나리오 |
| 1차 타깃 | Windows 11 + Chromium 최신 안정판 | 로컬 QA |
| 접근성 | 편집 UI의 키보드 조작, 버튼 레이블, 명도 대비 | 수동 검사 |

성능 시간 목표(미리보기 FPS 및 렌더 시간)는 보유 하드웨어와 에셋 크기를 기준으로 초기 측정 후 기준값을 확정한다. 근거 없이 보장하지 않는다.

## 5. 단계별 기능 요구사항 및 승인 조건

### P1. 기존 3D 모자이크·카메라 안정화 (Priority P0)

**요구사항**

- FR-101: 기존 소스, 의존성, 실행 스크립트, Next.js와 Remotion의 에셋 경로를 조사한다.
- FR-102: 이미지 36장을 그리드/불규칙 타일에 안정적으로 배치한다. 모든 타일은 고유 ID를 가진다.
- FR-103: 타일 크기, 간격, 둥근 모서리, Z축/회전값을 설정으로 제어한다.
- FR-104: `sceneState(t)` 형태의 순수 시간 함수로 카메라와 타일 상태를 계산한다.
- FR-105: 웹에서는 GSAP으로 현재 시간/사용자 인터랙션을 제어하되 렌더 결과는 동일 `sceneState`를 참조한다.
- FR-106: 영상에서는 `useCurrentFrame()`으로 시간을 계산하며 자체 무한 애니메이션 루프에 의존하지 않는다.
- FR-107: `public/photos` 경로 처리: 웹과 Remotion의 자산 URL 생성기를 분리하거나 환경별로 안전하게 정규화한다. Remotion의 로컬 자산은 `staticFile()` 활용.
- FR-108: `EACCES` 발생 시 포트 충돌/예약 포트를 안내하고 임의로 관리자 권한 실행·시스템 포트 삭제를 하지 않는다.

**승인 조건**: Windows PowerShell에서 웹/Studio 각각 구동, 이미지 36장 로딩, 특정 시점 스크럽 성공, 콘솔의 이미지 경로 에러 0건. 해당 조건 충족 전 P2 진입 금지.

### P2. 레퍼런스 모션 정밀 비교 (Priority P0)

**요구사항**

- FR-201: 참고 MP4에서 0s/1s/3s/6s/8s/종료 시점의 실제 프레임을 추출해 `references/`에 보관한다. 이 구간은 분석용 초기 샘플이며 실제 장면 분기점은 프레임 확인 후 수정한다.
- FR-202: 비교 항목을 타일 밀도/크기/간격, 색상, 기울기, FOV, 위치, 줌, 이동 방향, 속도곡선으로 구분한다.
- FR-203: 카메라 키프레임을 시간·position·rotation·FOV·easing으로 표현한다.
- FR-204: 줌아웃→기울기→대각 이동→타이틀 진입의 모션을 초기 프리셋으로 제공한다.
- FR-205: 레퍼런스/구현 프레임을 나란히 비교하는 QA 결과를 기록한다.

**승인 조건**: 주요 시점의 비교 캡처 6장 이상, 키프레임 테이블 작성, 사용자가 확인한 1차 모션 승인. 동일함을 수치로 과장하지 않으며 주관적 유사도는 수동 검토로 판단.

### P3. 브랜드·로고·음악·타이틀 편집 (Priority P0)

- FR-301: 이미지/SVG/PNG 로고 배치 및 위치·크기·투명도 조절.
- FR-302: 타이틀/부제, 글꼴, 크기, 정렬, 색상, 등장/퇴장 효과 조절.
- FR-303: 브랜드 컬러와 배경색 프리셋, 16:9 안전 영역 오버레이.
- FR-304: 사용자가 권리를 확보한 MP3/WAV 오디오 업로드, 볼륨·시작점·페이드인/아웃 설정.
- FR-305: 웹에서는 브라우저 자동재생 정책을 준수하여 무음 시작 및 사용자 제스처로 음악 재생.
- FR-306: 영상 렌더에서는 영상과 오디오가 프레임 기준으로 동기화되도록 한다.
- FR-307: 10초 기본 인트로 타임라인에서 0~7초 사진월, 7~10초 브랜드 엔딩이라는 초기 프리셋 제공(시간 자유 수정 가능).

**승인 조건**: 로고/타이틀/음악의 입력값 변경이 미리보기와 출력에 반영되고, 영상 종료 시 잘림·검은 프레임·소리 깨짐이 없음.

### P4. 이미지 업로드·템플릿 관리자 (Priority P1)

- FR-401: JPG/PNG/WebP 파일 업로드, 다중 선택, 썸네일/순서 변경, 삭제/교체.
- FR-402: 파일별 MIME/확장자/해상도/크기 검증과 실패 메시지 제공.
- FR-403: 36장 기본 템플릿 및 최소 3개 프리셋(모자이크 줌, 대각 패닝, 로고 리빌)을 제공한다.
- FR-404: 템플릿 적용 시 기존 업로드 자료 보존 여부를 명시적으로 선택하도록 한다.
- FR-405: 프로젝트 저장/불러오기/복제/이름 변경/삭제.
- FR-406: 프로젝트 데이터의 schemaVersion을 포함해 버전 변경 시 마이그레이션 가능하게 한다.
- FR-407: 자동 저장(디바운스)과 수동 저장 상태를 표시한다. 실패 시 사용자에게 알린다.

**저장 전략**: 1차 로컬 MVP는 프로젝트 설정 JSON + 로컬 파일 관리. 대량 원본 이미지를 브라우저 localStorage에 저장하지 않는다. 서버 업로드/API 또는 IndexedDB 방식 중 현재 실행 아키텍처에 맞게 선택하여 문서화한다. 다중 사용자 SaaS 전환 시 Supabase PostgreSQL + Storage + Auth를 검토한다.

**승인 조건**: 서로 다른 두 프로젝트를 저장하고 재시작 후 불러와 사진 배열·모션·브랜드 값이 유지됨. 깨진 업로드에 대해 편집기가 중단되지 않음.

### P5. MP4 렌더링·다운로드 UI (Priority P0, P4 이후 통합)

- FR-501: 프리셋(1080p/30fps) 렌더 제출 및 작업 ID 부여.
- FR-502: 상태 `queued`, `processing`, `completed`, `failed`, `canceled` 표시.
- FR-503: 프레임 카운트/단계 기반 진행률과 실패 오류 메시지 표시.
- FR-504: 파일 이름, 해상도, FPS, 예상하지 않은 길이 변경에 대한 검증.
- FR-505: 렌더 완료된 MP4 다운로드 및 결과 미리보기.
- FR-506: 렌더 실패 재시도/취소. 중복 클릭 방지.
- FR-507: 로컬 단일 사용자에서는 서버 프로세스(서버 측 렌더 작업)를 통해 렌더하며 브라우저 탭에서 직접 대용량 렌더를 수행하지 않는다.
- FR-508: 렌더 시 프로젝트 설정 스냅샷을 고정해 편집 중인 최신 변경이 기존 작업 결과를 바꾸지 않게 한다.

**승인 조건**: 10초 1080p/30fps H.264 MP4가 파일로 생성되고 재생기에서 열림. 300프레임, 영상 길이, 음성 재생, 마지막 프레임 검증. 실패/재시도/취소 경로 수동 테스트.

## 6. 기술 아키텍처

### 6.1 추천 기술

| 계층 | 도구 | 책임 |
| --- | --- | --- |
| 프론트엔드 | Next.js App Router + React + TypeScript | 웹 UI·편집기 |
| 디자인 | Tailwind CSS + shadcn/ui | 컴포넌트·토큰·접근성 |
| 3D | Three.js + React Three Fiber | 타일/카메라/텍스처 |
| 웹 모션 제어 | GSAP | 재생기/스크롤/인터랙션 |
| 영상 구성·렌더 | Remotion + @remotion/three | 프레임 기반 3D MP4 |
| 렌더 프로세스 | Node.js 로컬 서버 프로세스 | 작업 큐·실행·상태 전달 |
| MVP 저장 | 프로젝트 JSON + 로컬 에셋 디렉터리 | 단일 관리자 지속성 |
| 차기 SaaS | Supabase / PostgreSQL / Storage | 인증·메타데이터·객체 저장 |
| 검증 | TypeScript/ESLint + 단위/통합/E2E | 품질 게이트 |

**버전 정책**: 현 저장소의 잠금 파일 및 호환성 확인 후 각 패키지의 안정 버전을 고정한다. 검증하지 않은 최신 버전 일괄 업데이트 금지.

### 6.2 핵심 설계 원칙

```text
[ProjectConfig(JSON)] ───┬──> [Asset Manifest / Asset Resolver]
                        └──> [Pure Scene Evaluator(t)]
                                   │
                     ┌─────────────┴─────────────┐
                     ▼                           ▼
          [Next.js Web Player]        [Remotion Composition]
          [GSAP time/interaction]     [useCurrentFrame / fps]
                     │                           │
            [R3F Canvas]                [@remotion/three]
                     │                           │
              [웹 인트로]              [MP4 Render Worker]
                                                 │
                                           [다운로드 UI]
```

- 공통 기능은 **타일 배열 계산, 키프레임 보간, 카메라 포즈, 브랜드 설정**이다.
- 실행 환경에 종속된 기능은 **시간 공급자, 3D 렌더러 래퍼, 에셋 URL, 오디오 재생, 다운로드**다.
- `performance.now()`, `Date.now()`, `Math.random()`, 프레임마다 증가하는 누산 상태를 영상 씬의 핵심 상태 계산에 사용하지 않는다. 난수가 필요하면 프로젝트에 저장된 seed를 사용한다.
- Remotion 안에서 `useFrame()`으로 애니메이션하지 않는다. `@remotion/three`와 `useCurrentFrame()` 사용.
- 동일한 시간 `t`에 대한 웹/영상 결과가 가능한 한 같은 카메라·레이아웃 상태를 갖도록 한다.

### 6.3 제안 폴더 구조(기존 소스에 맞춰 조정)

## 7. 데이터 계약 (개념 스키마)

코드 작성 전에 아래 필드·의미를 지켜야 한다. 타입 상세 설계는 후속 `DESIGN.md`에서 확정한다.

| 엔터티 | 필수 필드 | 역할 |
| --- | --- | --- |
| Project | id, schemaVersion, title, durationSeconds, fps, resolution, createdAt, updatedAt | 최상위 프로젝트 |
| Asset | id, projectId, type, storageKey, mimeType, width?, height?, sizeBytes, order | 사진/로고/음악 |
| Tile | id, assetId, x, y, z, width, height, rotation, radius, crop | 씬 배치 |
| CameraKeyframe | id, timeSeconds, position, rotation, fov, easing | 카메라 경로 |
| BrandOverlay | logoAssetId?, title, subtitle?, style, startSeconds, endSeconds | 브랜드 표시 |
| AudioTrack | assetId, startSeconds, trimStartSeconds, volume, fadeInSeconds, fadeOutSeconds | 배경 음악 |
| Template | id, name, schemaVersion, tileLayout, cameraTrack, defaultBrand | 재사용 프리셋 |
| RenderJob | id, projectId, projectSnapshot, status, fps, resolution, outputPath?, error?, timestamps | 렌더 추적 |

**유효성 조건**: 참조하는 `assetId`는 존재해야 하고, 타임라인 범위는 `0 ≤ start ≤ end ≤ duration`, fps > 0, width/height > 0, 파일 크기 및 유형을 업로드 시 검사한다. 저장된 프로젝트는 화면 상태가 아니라 **정규화된 JSON 데이터**를 기준으로 재생성한다.

## 8. 카메라/타임라인 기본 프리셋

| 구간 | 카메라 액션 | 영상 연출 | 조절 가능 값 |
| --- | --- | --- | --- |
| 0.0–2.0초 | 근접 이미지 → 줌아웃 | 이미지 공간 도입 | 줌, FOV, ease |
| 2.0–4.0초 | 틸트 회전 + 외곽 이동 | 배열 규모 노출 | pitch/roll, 위치 |
| 4.0–7.0초 | 대각 패닝 | 타일 사이 이동 | 경로, 속도, 흔들림 |
| 7.0–9.0초 | 카메라 안정화 | 브랜드 영역 확보 | 위치/조명/배경 |
| 9.0–10초 | 로고/타이틀 엔딩 | 브랜드 확정 | opacity, scale, 음악 페이드 |

이는 개발용 **초기안**이지 원본 영상을 정밀 계측한 결과가 아니다. P2에서 사용자가 제공한 실제 참고 프레임과 비교해 수정한다.

## 9. API 및 렌더 워크플로(초안)

| 엔드포인트 | 메서드 | 역할 |
| --- | --- | --- |
| `/api/projects` | GET/POST | 목록/생성 |
| `/api/projects/[id]` | GET/PATCH/DELETE | 로드/수정/삭제 |
| `/api/projects/[id]/assets` | POST | 파일 업로드 |
| `/api/templates` | GET | 템플릿 목록 |
| `/api/renders` | POST | 프로젝트 스냅샷 기반 렌더 시작 |
| `/api/renders/[jobId]` | GET | 작업 상태/진행률 |
| `/api/renders/[jobId]/cancel` | POST | 렌더 취소 |
| `/api/renders/[jobId]/download` | GET | 결과 파일 다운로드 |

모든 API에는 입력 스키마 검증, 파일 경로 정규화 및 프로젝트 접근 권한 경계가 필요하다. 로컬 MVP라도 파일명 그대로 서버 경로를 조합하거나 사용자 제공 URL을 제한 없이 가져오지 않는다. 서버 재시작/렌더 실패 시 임시 파일을 정리한다.

## 10. 오류 대응 및 복구 요구사항

| 상황 | 예상 원인 | 필수 처리 |
| --- | --- | --- |
| `listen EACCES 0.0.0.0:3000` | Windows 예약 포트/접근 정책 등 | 바인딩 호스트·포트 변경, 예약 범위 확인, 사용자 안내 |
| `Port 3000~3097 busy` | 사용 중이거나 예약된 범위 | 사용 가능한 포트 선택/명시, 무단 프로세스 종료 금지 |
| `Could not load /photos/01.jpg` | Remotion 에셋 URL 차이 또는 파일 누락 | `staticFile()` 사용/파일 존재 검사, 대체 이미지 표시 |
| WebGL context lost | GPU/메모리 과부하 | 텍스처 크기 축소, 에셋 수 제한, 오류 복구 안내 |
| 렌더 중 브라우저 종료 | 렌더링 프로세스 설계 | 작업 상태 유지, 취소/재시도 정책 |
| 지원하지 않는 이미지 | 잘못된 MIME/코덱 | 업로드 즉시 검사, 변환 안내 |
| 음악 자동재생 차단 | 브라우저 정책 | 무음 미리보기 시작 + 수동 오디오 허용 |
| 렌더 이미지 공백 | 텍스처 로딩 완료 전 캡처 | 에셋 준비 완료 대기, 로딩 실패 추적 |

## 13. 멀티에이전트 개발 운영 규칙

- **총괄 에이전트(Opus 계열)**: 요구사항/범위/수용 기준/의존성 조율. 변경 승인.
- **공동 설계·디자인(Claude Sonnet + Codex)**: IA/컴포넌트/카메라 수학/접근성/테스트 시나리오를 상호 리뷰.
- **구현 워커(Sonnet 또는 Codex)**: 비충돌 파일 범위로 티켓 분리, 타입/테스트 포함 구현.
- **독립 리뷰어(Codex 또는 Opus)**: 회귀 테스트, 결정적 렌더 검증, 문제 재현.
- 모든 작업은 `PRD.md` → `DESIGN.md` → 티켓 → 구현 → 테스트 → 리뷰 순서.
- 에이전트 간 병렬 작업은 파일/인터페이스 오너를 먼저 고정하고 동일 파일 동시 수정 금지.
- PRD 수정 필요 시 요구사항 ID, 변경 이유, 영향받는 단계, 승인 여부 기록.
- 디자이너가 Figma 유료 계정 없이도 작업 가능하도록 텍스트 와이어프레임, Storybook(선택), 브라우저 화면 캡처로 검수.

## 14. 예상 비용과 운영 제약

- **로컬 MVP**: 기존 PC에서 직접 개발·미리보기·렌더 가능. 신규 서버 비용 없이 시작하는 설계.
- **렌더 비용**: 로컬 CPU/GPU 시간, 스토리지, 전기 사용량이 소요되며 영상 길이·사진 해상도·장면 복잡도에 따라 변동.
- **SaaS 전환 후**: 스토리지/전송량/렌더 컴퓨팅/큐 비용을 건당 계측해야 함.
- **Remotion 라이선스**: 개인 및 소규모 조직의 사용 자격과 템플릿 기반 상용 자동화/서비스 조건은 사업화 시점에 최신 공식 약관으로 재확인. 무료 사용을 SaaS 전체의 무제한 이용 허가로 해석하지 말 것.
- **저작권**: 벤치마킹은 모션 구조 중심. 원본 영상 이미지·로고·음악 재사용은 별도 권한 확보가 필요.

## 15. MVP 이후 수익화·자동화·확장

### 15.1 검증 가능한 상품화 가설

- 크리에이터용 브랜드 인트로 템플릿 판매.
- 사진 교체·로고 삽입 기반 맞춤 인트로 제작 대행.
- 웹 히어로 + 유튜브 인트로 통합 제작 패키지.
- 이후 사용량 기반 영상 렌더 SaaS.

이 항목들은 **수익 가능성 가설**이며 확인된 수요/매출이 아니다. 우선 제작 샘플 3종과 랜딩페이지로 관심·견적 문의·유료 주문 전환을 검증한다.

### 15.2 확장 순서

1. 로컬 단일 사용자 완성 및 렌더 성공.
2. 샘플 영상 3종/랜딩/사전예약 또는 유료 제작 의뢰 검증.
3. 템플릿·브랜드 키트·반복 렌더 작업 자동화.
4. Supabase Auth/Storage, 프로젝트 테넌트 분리, 렌더 큐 도입.
5. 결제/사용량 제한/관리자 분석 및 API 연동.
