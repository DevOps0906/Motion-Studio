## 연결 절차

1. 설치·버전·실행 문서·플러그인·라이선스 조건 확인.
2. 로컬 엔드포인트·전송·인증 지원을 클라이언트별로 확인. 확인하지 않은 설정을 복사하지 않는다.
3. 기능 목록과 입력 스키마를 탐색하고 읽기 전용 조회부터 검증한다.
4. 별도 테스트 문서에서 작게 쓰기 → 결과 조회 → 저장 → 다시 열기 → 복구 시험.
5. 통과한 기능만 Motion Studio의 어댑터 기능 표에 승격한다.

## 실행 계약

- 한 편집 세션에는 한 작성자만 허용한다. 다른 에이전트는 읽기·별도 파일 검토를 수행한다.
- 작업마다 sessionId, writerLease, commandId, 예상 revision, 변경 전 저장점, 변경 후 결과·화면·로그를 남긴다.
- 타임아웃 시 무조건 재실행하지 않는다. commandId와 현재 문서 상태를 조회해 중복 생성 여부를 먼저 확인한다.
- 파괴적 변경은 별도 원본 사본에서 검수한다. 호스트·포트·인증 정보를 문서나 로그에 비밀값으로 기록하지 않는다.
- 연결 실패는 integration 상태로 표시하며 모델 변환·뷰어의 수동 경로와 구분한다.

MCP는 도구 호출 계층이다. 단위 검증·파일 변환·렌더·법규 검수를 대신하지 않는다. 이번 문서는 연결 설정을 실제로 변경하지 않는다.
