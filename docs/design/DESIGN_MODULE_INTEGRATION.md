# 디자인 모듈 적용 계획과 구현

## 참고 원본

사용자가 지정한 [nomad-design-modules](https://github.com/DevOps0906/nomad-design-modules) master의 커밋 `88c1022ad41d24139cb835e748bf6200c22a8d37`을 확인했다(2026-10-30).
참고 문서는 _design-guide/DESIGN_PRINCIPLES.md, DESIGN_SYSTEM.md, BLOG_SKIN.md, LANDING_PERSUASION.md, MOTION_GSAP.md다.
원본은 주로 설계 가이드와 랜딩 템플릿이다. 외부 가이드의 경로나 라이브러리 구성을 Motion Studio의 실행 지침으로 취급하지 않고, 현재 제품에 맞는 패턴을 선별했다. 원본에 별도 라이선스 표시는 없으며, 사용자 지정 저장소를 참고해 자체 CSS를 작성했다. 제3자 사진·로고·후기·PDF·템플릿 배포 파일은 가져오지 않았다.

## 부족한 부분과 적용

기존에는 레이아웃 3종과 강조색·테마를 고를 수 있었지만 서체·여백·모서리·모션의 일관된 조합을 선택할 수 없었다. 웹사이트 제작기에 디자인 키트를 추가했다.

| 키트 | 구성 | 첫 화면 모션 |
| --- | --- | --- |
| 기존 디자인 유지 | 이전 프로젝트 외형 유지 | 기존 모션 |
| 미니멀 | 시스템 서체, 직선, 56px 섹션 여백 | 대표 이미지에만 짧은 등장 |
| 퍼블리케이션 | 세리프 제목, 2px 모서리, 88px 여백 | 정적 표시 |
| 포트폴리오 | 시스템 서체, 24px 모서리, 64px 여백 | 대표 이미지에만 부드러운 등장 |

모바일 컨테이너 600px 이하에서는 새 키트의 세로 여백을 36px로 줄인다. 시스템의 동작 줄이기 설정에서는 애니메이션을 끈다. 토큰은 lib/website-styles.ts의 CSS 변수로 관리하며 편집기 미리보기와 독립 HTML이 같은 스타일을 사용한다. 레이아웃 선택과 키트는 독립적이고, 메타데이터를 가져와도 선택한 키트가 보존된다. 기존 저장 데이터에 키트가 없으면 기존 디자인 유지로 정규화한다.

## 다른 제작기와 다음 적용 순서

- 홈페이지형 블로그 디자인: 기업형·개인형·매거진형, PNG/투명 위젯/좌표표/설치 안내서는 이미 구현되어 중복 기능은 추가하지 않는다. BLOG_SKIN의 PC·모바일 별도 검수와 수동 설치 원칙을 계속 따른다.
- 영상: 기존 13개 인트로와 해상도 선택을 유지한다. 웹 모션과 영상 카메라는 실행 환경이 달라 CSS 키트를 영상 프리셋으로 간주하지 않는다.
- 설득형 랜딩: 이후 실제 제공 정보가 있을 때 기존/제품 방식 비교, 작업 순서, 근거 링크를 편집 모듈로 확장한다. 현재 후기·고객 수·성과를 생성하거나 템플릿의 수치를 복제하지 않는다.
- 3D 히어로·스크롤 고정·새 UI 라이브러리 일괄 교체는 이번 범위에 포함하지 않는다. 실제 모델과 성능 검증이 필요한 별도 단계다.

## 확인

키트 허용 목록 검증, 기존 데이터 기본값, HTML 출력 클래스, 메타데이터 가져오기 시 키트 유지, 타입 검사와 기존 회귀 테스트를 수행한다. 원본 저장소 전체를 런타임 의존성으로 추가하지 않아 빌드 시 GitHub 연결은 필요 없다.
