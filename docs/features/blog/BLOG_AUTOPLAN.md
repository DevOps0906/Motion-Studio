# 주소·레퍼런스 중심 네이버 블로그 스킨 생성

## 입력과 결과

/blog-skins 상단에서 네이버 블로그 주소, 레퍼런스URL, 선택형aside(없음/왼쪽/오른쪽)만 입력한다. 주소기반 자동기획은 브랜드명·헤드라인·소개·스타일·기본 메뉴를 채우고 resvg PNG 미리보기를 생성한다. 선택해 둔 로고·대표 이미지·공개 투명 이미지URL은 유지한다. 원본 블로그 주소·참고URL·aside 위치는 프로젝트와 metadata.json에 저장된다. 생성 후 상세 편집과 저장·ZIP 출력을 사용할 수 있다.

## 실제 AI 연결과 현재 상태

현재 환경에는 AI 서비스 키가 설정되지 않아 규칙 기반 자동기획으로 동작한다. UI와 결과 메시지는 AI 결과라고 표시하지 않는다. 실제 OpenAI Responses 호출 코드를 구현했고 JSON Schema 출력과 서버 검증을 적용했다. 제공자 경로는 모의 응답으로 검증했으며 실제 API 호출은 아직 검증하지 않았다.

운영자가 서버 환경변수 또는 .env.local에 OPENAI_API_KEY와 OPENAI_BLOG_MODEL을 설정하고 서버를 재시작하면 AI 서비스를 사용할 수 있다. 모델은 운영자가 현재 계정에서 사용할 수 있는 Responses·Structured Outputs 지원 모델을 지정한다. 브라우저에 키를 넣지 않는다. 키와 모델이 모두 있어야 연결됨 상태를 표시한다. 실제 AI 호출은 운영자 로그인 확인 후에만 허용하며, 공개 운영자 이메일은 REQUIREMENTS_ADMIN_EMAILS를 따른다. AI 사용을 해제하면 규칙 기반 자동기획으로 동작한다. 설정됨 상태는 자격 증명·사용한도 검증 성공을 의미하지 않는다.

공식 구현 참고: https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses

## 공개 정보 확인과 경계

네이버 주소를 블로그ID가 있는 blog.naver.com 형식으로 정규화한다. 공개 메타데이터 요청은 blog.naver.com/m.blog.naver.com과 지정한 디자인 레퍼런스 도메인으로 제한하며 리다이렉트를 따라가지 않는다. 요청6초·HTML256KiB한도를 적용한다. 임의 레퍼런스URL은 기록할 수 있지만 허용 목록 밖 주소의 내용을 서버가 가져오지 않으며 읽지 못했다는 메시지를 표시한다. 전체 디자인/DOM/스크린샷 분석 기능은 아니다.

읽지 못한 내용과 업종·실적·연락처를 추측하지 않는다. 기본 메뉴는 실제 입력한 블로그 홈과 전체글 주소를 사용한다. AI 메뉴명도 확인된 블로그 주소로만 연결하며 실제 카테고리URL은 상세 편집에서 검수한다. 외부 페이지 데이터는 신뢰할 수 없는 참고 데이터로 프롬프트에 전달하고 그 안의 지시를 따르지 않도록 한다. 고객·레퍼런스의 로고·사진을 무단으로 복사하지 않으며 생성 이미지 대신 현재 라이브러리 이미지 또는 자체 브랜드 그래픽을 사용한다. AI 사용 시 공개 메타데이터와 입력URL이 OpenAI로 전달되고 store:false를 지정한다.

## aside 선택

aside는 네이버에 자유롭게 HTML aside를 설치하는 기능이 아니다. 프로필·카테고리·문의 동선을 담는 사이드 레이아웃을 이미지와 투명 위젯으로 만드는 옵션이다. 왼쪽x275 또는 오른쪽x1500에 폭170px의 프로필 패널과 메뉴링크를 배치한다. 링크좌표는170×48, 메인메뉴는170×100이며 메뉴5개 기준 총10위젯으로20개 이내다. aside의 위치와 메뉴는 SVG/PNG·위젯HTML·좌표JSON/CSV·metadata에 반영된다. 네이버에서 선택한 레이아웃에 맞춰 수동 보정하고 PC·모바일을 별도 검수해야 한다.
