# 고객 개발요구사항 진단 · 상담 접수

## 고객 흐름

홈페이지 제작기 상단의 개발요구사항 카드 → /website-requirements → 홈페이지/블로그/함께 선택 → 목적과 기능 체크 → BASIC/BUSINESS/PREMIUM 또는 블로그 단독 추천 → 담당자 정보·동의 → 보내기 → 접수번호 확인.

추천은 명시적인 규칙을 따른다. 소개 목적은 BASIC, 성장·CMS·CRM·전환 분석·단순 자동화는 BUSINESS, 브랜드 경험·영상 연출·3D·복잡한 승인 업무는 PREMIUM을 우선한다. 회원·예약·결제와 다국어는 BUSINESS 이상에서 별도 범위를 확인한다. 블로그만 선택하면 홈페이지 등급을 강제 추천하지 않는다. 예산과 일정은 견적 협의용으로 기록하며 높은 복잡도를 낮은 등급으로 바꾸는 근거로 쓰지 않는다.

홈페이지형 블로그는 네이버 스킨·타이틀·투명 위젯·메뉴 링크·좌표표·설치 안내서를 만드는 옵션이다. 네이버 수동 적용과 PC·모바일 별도 검수가 필요하다. 독립 웹사이트의 CMS·결제·3D 기능과 같다고 표시하지 않는다.

## 접수와 운영자 화면

POST /api/website-requirements는 담당자명·회사명·전화번호·이메일·요구사항·서버에서 다시 계산한 추천·동의 버전을 .local-data/requirements.sqlite에 저장한다. Node 24에서 제공하는 node:sqlite DatabaseSync를 사용한다. 입력 길이·전화·이메일·옵션·동의를 검증하고 파라미터 바인딩 SQL, 접수 키 중복 방지, 이메일별 15분5건 제한, 허니팟을 적용했다. 고객 응답에는 접수번호만 반환한다. 외부 Google이나 이메일로 개인정보를 전송하지 않는다.

운영자 화면 /requirements-inbox는 최신100건의 연락처·요구·추천 이유를 표시한다. 로그인한 계정만 접수 API를 조회할 수 있다. 로컬 호스트에서는 로그인한 로컬 운영자가 확인한다. 공개 배포에서는 REQUIREMENTS_ADMIN_EMAILS에 허용할 계정 이메일을 쉼표로 지정해야 한다. 공개 호스트에서 설정이 없으면 조회를 거부한다. 외부 고객은 로그인 없이 동의 후 제출할 수 있다.

수집 목적은 제작 상담·견적 협의이며 동의 없이도 진단할 수 있다. 보관 기간은90일이며 DB에 접근할 때 만료 데이터를 정리한다. 서버 운영 중 정기적 접속 또는 별도 스케줄 작업을 유지하고 백업도 같은 보관 정책에 맞춰 운영해야 한다. DB·WAL·SHM파일은 저장소에 커밋하지 않는다. 공개 운영 전 실제 사업자의 개인정보 처리 안내와 관리 절차를 확정한다.

구글시트 자동 동기화는 연결하지 않았다. 운영자 화면의 CSV 다운로드를 구글시트에서 가져올 수 있다. CSV는 UTF-8 BOM과 셀 인용, 수식으로 해석될 수 있는 접두어 방어를 적용한다. 고객 데이터는 운영자가 다운로드를 누를 때만 파일로 출력한다.

## 고객에게 보내는 방법

온라인 주소를 복사해 전달한다. 현재 실행 중인 localhost/127.0.0.1 주소는 외부 고객에게 접속되는 주소가 아니다. 도메인과 HTTPS로 공개 배포한 후 그 주소를 사용해야 실시간 접수가 가능하다. 폼은 현재 서버의 같은 출처 API로만 전송한다. 정적 HTML 호스팅만으로 DB 접수가 작동하지는 않는다. Node 서버와 영속 쓰기 가능한 디스크가 필요하며 서버리스 임시 디스크에는 이 SQLite 구성을 그대로 배포하지 않는다.

다운로드하는 HTML은 네트워크 없이 체크·추천·결과 JSON 출력이 가능한 진단 파일이다. 개인정보 보내기는 포함하지 않으며, 온라인 접수 페이지 또는 결과 파일의 수동 전달을 안내한다. 고객용 파일에 관리자의 세션·DB·연락처 목록은 포함하지 않는다.

## 검증

추천 경계·블로그 단독/추가·회원/결제 옵션·오프라인 파일 테스트를 추가했다. 실제 브라우저에서 진단·접수·운영자 조회·미인증 차단·모바일 화면·오프라인 추천을 확인한다. QA로 만든 접수와 계정만 삭제하고 기존 고객 기록은 유지한다.


## 실시간 추천·신청 진입

선택한 목적·제작물·기능이 바뀌면 제출 전에 상단 고정 추천 표시가 즉시 갱신됩니다. 기능별 상품 범위를 카드에 표시하고, GSAP로 선택 카드와 추천 표시를 0.25~0.28초 동안 강조합니다. GSAP context와 matchMedia 정리로 빠른 재선택·화면 이탈 시 모션을 정리하며 prefers-reduced-motion에서는 정적으로 표시합니다. 개인정보·예산 입력에는 모션을 반복하지 않습니다.

진단·상품·홈페이지 랜딩의 제목과 카드 간격을 축소했습니다. 홈페이지 랜딩에 비로그인 신청 링크와 개발요구사항 링크 복사 버튼을 추가했고, 같은 복사 버튼을 제작기와 고객 진단에도 제공합니다. 클립보드 접근이 거부되면 직접 복사할 주소 입력창을 표시합니다. 현재 출처를 기준으로 주소를 만들며 로컬 주소는 외부 접속용이 아님을 안내합니다.

구현 참고: [GSAP context 공식 문서](https://gsap.com/docs/v3/GSAP/gsap.context()/).


## 등급 구분·일정·레퍼런스

홈페이지 목적 선택 버튼을 BASIC(블루그레이)·BUSINESS(라벤더)·PREMIUM(샴페인)으로 구분했습니다. 기능은 BASIC → BUSINESS → PREMIUM 순으로 묶고 각 구역 옆에 해당 등급의 홈페이지 레퍼런스 카드를 배치합니다. 현재 실제 레퍼런스가 없어 준비 중 상태이며 가짜 링크를 만들지 않습니다. `lib/website-reference-showcase.ts`의 등급별 url에 인증 정보 없는 http/https 주소를 등록하면 새 탭으로 열리는 링크 카드로 전환됩니다. 내부 HTML 구조 그림은 자리 표시용이며 실제 사이트 스크린샷이 아닙니다.

희망일정은 네이티브 date 입력과 캘린더 열기 버튼으로 선택하며 ISO 날짜(YYYY-MM-DD)를 답변·DB·CSV에 유지합니다. 오프라인 진단 HTML도 등급별 기능 구분과 날짜 선택을 제공합니다. 기존에 접수한 자유 형식 일정은 수정하거나 삭제하지 않습니다.
